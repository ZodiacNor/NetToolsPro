# NetTools Pro v1.10.0

Released 2026-11-04. This release includes the workspace, Bluetooth, Windows build,
and diagnostic fixes developed since v1.9.0.

## Downloads

- `NetToolsPro-linux-x86_64.bin` — Linux x86_64, built and tested on Fedora.
- `NetToolsPro-windows-x64.exe` — Windows x64 portable executable.
- `SHA256SUMS.txt` — SHA-256 checksums for both executables.

Download all three assets from the
[v1.10.0 release](https://github.com/ZodiacNor/NetToolsPro/releases/tag/v1.10.0).

On Linux, verify the downloaded files from their directory with:

```bash
sha256sum -c SHA256SUMS.txt
chmod +x NetToolsPro-linux-x86_64.bin
./NetToolsPro-linux-x86_64.bin
```

If you downloaded only one executable, compare its hash with the matching line
in `SHA256SUMS.txt`. On Windows, calculate the hash with PowerShell:

```powershell
Get-FileHash .\NetToolsPro-windows-x64.exe -Algorithm SHA256
```

## Highlights

- Open tool pages on first use, find tools with Ctrl+K, and use dashboard shortcuts.
- Read dashboard statistics in the background, with live upload/download rates.
- Preserve settings and favorites across executable upgrades using per-user storage,
  atomic saves, and migration from supported older JSON files.
- Discover Bluetooth devices on Fedora/Linux through BlueZ, with BLE/Classic modes,
  filtering, detailed properties, and local JSON/CSV export. The Bluetooth backend
  is Linux-only; Windows Bluetooth scanning is not implemented.

## Fixes

- Preserve uncertain UDP results as `OPEN|FILTERED` and classify TCP timeouts correctly.
- Validate scan options, limit queued probes, and restore scan controls after cancellation.
- Enforce ARP process deadlines and handle stderr without blocking scan output.
- Correct Windows ARP address matching and default-route selection.
- Use an external Python interpreter for Python scripts in packaged Script Lab.
- Preserve known Bluetooth properties when BlueZ sends partial updates.
- Prevent duplicate bandwidth timers and incorrect rates after interface/counter changes.
- Require Pillow 13.0.0 or newer; source and build setups require Python 3.11 or newer.

## Verification and limits

- Linux: 66 unit tests, 65 passed and one hardware Bluetooth test skipped.
- Windows CPython under Wine: 66 unit tests, 61 passed and five skipped.
- All 25 GUI pages passed on Linux and Wine, including synthetic camera rendering,
  fullscreen/restore, search, scan cancellation/restart, and bandwidth timers.
- Both packaged executables passed 15-second isolated startup checks without stderr.
- Physical Windows, native Windows tray behavior, real camera streams, Bluetooth radio
  scanning, and actual network scan responses still need hardware acceptance testing.
- An in-flight reverse-DNS lookup can delay scan cancellation.
- Other Linux distributions may require running from source or rebuilding locally.

Camera playback and the protected camera/glyph GUI baseline remain unchanged.
Python is not required to launch the packaged executable; Script Lab Python scripts
still need an external Python installation.
